# 资料库 · 关系页 + 数据生长 — 可开发规格 v1

> 状态：已定案（2026-09-05）  
> 审美：简洁 · 大方 · 现代 · 高级  
> 目标：取代设置里旧「数据库」大表，成为 idolMatrix 主站地基

---

## 0. 一句话

新建/打开组合后，**家永远是关系页**；数据不够时用「开始/继续生长」——搜索维基百科 / Fandom / 百度百科等，经 AI 分步提案、人审后写入，逐步长出小分队、成员及详情、专辑、歌曲及详情。

---

## 1. 产品定位

| 项目 | 定案 |
|------|------|
| 主入口 | 主站「资料库」`/db` → 组合工作台 `/db/groups/:uid` |
| 取代 | 设置 → 数据库（日常 CRUD / 旧关联视图退出主路径） |
| 成功标准 | 直观（一眼看网）、可靠（链接为准 + 冲突必审 + 可锁）、关联强（实体可互点）、可生长（空白也能从名字开始） |
| 与入库关系 | 入库把视频挂到**已生长的网**上；网是地基，入库是下游 |

## 2. 首屏与模式（已定 A + 轻 B）

### 2.1 家：关系页（查看态）

- 路由：`/db/groups/:uid`（可后续支持艺人/专辑工作台，P0 以组合为中心）
- 布局（克制三栏气质，对齐已定视觉）：
  - **左**：实体列表/搜索（组合；可切艺人/专辑为 P1）
  - **中**：英雄卡 + 小分队 + 现任/历史成员 + 专辑（可展开曲目）
  - **右**：问题列表 / 或点选后的编辑抽屉
- 顶栏次要操作：「继续生长」「用链接更新」

### 2.2 空态 / 低完整度（A + 轻 B）

- **A（默认）**：新建组合后进入关系页空态；中区大按钮 **「开始生长」**
- **轻 B**：若完整度低于阈值（建议 `< 30` 或「无成员且无专辑」），首次进入**自动打开生长层**（不必多点一次），但路由仍留在关系页
- 生长中途离开再回来：仍落在关系页；CTA 文案改为 **「继续生长」**，并提示卡在哪一步

### 2.3 生长态（层/抽屉，不是另一个家）

- 形态：关系页上的右侧大抽屉或居中面板（同一视觉语言），**不要**整页跳进旧式 admin 向导
- 关闭生长层 = 回到关系页看网

## 3. 数据生长流

### 3.1 来源

- 系统搜索候选：**维基百科（含多语言） / Fandom / 百度百科**（可扩展 Wikidata）
- 用户可多选候选 + 手动粘贴多个 URL
- 原则：只根据用户采纳的链接抽取；冲突必审；禁止无来源凭空编造关键事实

### 3.2 分步节奏（P0 必须按步，禁止默认「一次勾选一大包」）

| 步 | 名称 | 写入内容 | 完成判据（示例） |
|----|------|----------|------------------|
| 1 | 身份与公司 | 名/别名/出道日/类型/描述；公司关系（含起止若有） | 至少有出道日或描述之一 + 公司或明确跳过 |
| 2 | 小分队 | 子组合 + 与母团关系 + 成员名列表 | 无则跳过；有则建组并挂成员 |
| 3 | 成员轨迹 | 现任/历史、加入/退出、担当；对库消歧 create/link | 至少 N 名现任或用户确认「仅这些」 |
| 4 | 成员详情 | 生日/出生地/多语言名/简介/外链（可按人再拉链接） | 核心成员关键字段达阈值或用户跳过 |
| 5 | 专辑 | 碟志列表、类型、日期、封面；`release_artist` 指向本组合 | 用户确认本批专辑 |
| 6 | 歌曲 | 每碟曲目 → Song + AlbumTrack；可选署名 | 所选碟曲目写入或标记失败可重试 |

每步：`选链接（可复用上步）→ AI/抽取提案 → 只审本步 → 写入 → 关系页刷新 → 下一步`。

### 3.3 提案与裁决

- 每项提案带：`action`（create / link / exists / skip）、`sources[]`、冲突标记、疑似重复
- 高置信自动勾选；冲突/疑似重复默认不自动勾选
- 字段锁：已锁字段不覆盖；手动改过后自动锁（沿用现逻辑）
- 写入结果回执：新建/挂接/跳过数量；失败可重试本步

## 4. 关系页能力（查看 + 轻编辑）

### 4.1 P0

- 成员：点击 → 抽屉改 membership（日期/状态/担当）+ 艺人基础字段
- 专辑：列表可展开曲目；曲数为 0 时提示「补曲目」入口（进生长步 6 或单碟生长）
- 小分队：点击进入该组合工作台
- 问题轨：展示本组合 issues；P0 至少能跳到对应区块/抽屉

### 4.2 P1

- 公司从链接生长（补齐「后续支持」缺口）
- 问题一键修复（打开对应编辑或生长步）
- 左栏切艺人/专辑中心
- 设置旧数据库入口降级文案：「请使用资料库」+ 隐藏或折叠高级表

### 4.3 P2

- 成员级「再搜该人百科继续长」
- 全局体检与关系页深链完全打通
- ~~移除/归档 `SettingsDatabasePanel` 中日常路径与旧 `DbRelationCanvas`~~（已完成：全屏关联画布已从设置→数据库移除；面板内联关联浏览与高级表仍保留）

## 5. 信息架构与路由

```
/db                 资料库总览（体检，可保留）
/db/list            组合列表（完整度、问题摘要）→ 打开工作台
/db/groups/:uid     关系页（家）+ 生长层
```

主导航「资料库」指向上述；**设置不再承担建档主路径**。

新建组合：

1. 列表或快捷「新建组合」→ 仅需名称（及可选类型）  
2. 创建成功 → `router.push(/db/groups/:uid)`  
3. 空态大按钮 / 低完整度自动打开生长层

## 6. 技术要点（演进，不推倒 schema）

### 6.1 复用

- 现有：`Group` / `GroupMembership` / `GroupCompanyRelation`(已有起止) / `Album`+`release_artist_*` / `AlbumTrack` / `Song` / `external_links` / entity locks
- 现有 API 雏形：`/db/groups/:uid/workspace`、`source/search`、`source/preview`、`source/apply`

### 6.2 需要增强

- **preview/apply 按 step 参数化**（只返回/只应用本步提案），避免一次甩全包
- 搜索源扩展：**百度百科**（与维基、Fandom 并列）
- 专辑展开曲目：workspace 带回 tracks 或按需 `GET` 曲目
- 生长任务可选持久化（当前步、已选 URL），便于「继续生长」
- UI：重做 `DbGroupWorkspace` 为「关系页壳 + GrowthSheet」，去掉 diff 大表作为默认心智（对照可留在步骤内的精简列表）

### 6.3 明确不做（本规格范围外）

- 力导向全景关系图 / 赛博 HUD
- 推倒重做整库 schema
- 入库 AI 大改（下游；网稳后再做专辑反查等小优化）

## 8. 分期与验收

### P0（取代日常旧库的最小可用）

1. 关系页查看态达标（成员/小分队/专辑可展开曲目）  
2. 空态「开始生长」+ 低完整度自动拉起  
3. 生长分步 1→3→5→6 跑通（步 2、4 可简化但入口在）  
4. 维基 + Fandom 搜索/粘贴可用；百度百科至少支持手动 URL 抽取或搜索之一  
5. 设置数据库入口增加「请优先使用资料库」引导  

**验收脚本（izan 示例）**

1. 新建组合 `izan` → 落到空关系页，见「开始生长」  
2. 搜索并勾选百科链接 → 步 3 写入成员 → 关系页出现成员  
3. 继续生长专辑 → 展开可见曲目  
4. 手动改一成员日期 → 字段锁生效，再生长不覆盖  

### P1

- 公司链接生长、问题可点修、百度百科搜索体验、旧库入口降级

### P2

- 成员深链再生长、旧面板退役、全局体检打通
