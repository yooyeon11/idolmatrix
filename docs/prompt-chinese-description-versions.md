# 中文简介（`chinese_description`）提示词 · 三个世代对照

## 世代 1 · 原版（v3.6.7 之前）

**来源**：`backend/app/services/__pycache__/ai_service.cpython-310.pyc`（mtime **Sep 15 20:14**，
早于 9/22 的全部改动）原始字节抽取，逐字还原。同时与 `memory/2026-09-22.md:182` 记录的「旧口径」**完全一致**。

```
- chinese_description: 中文简介（用中文根据视频内容生成 2-4 句话，介绍这是什么演出/舞台/节目、表演者与曲目等；不要照抄原始简介原文）
```

**特点**：一行，自由发挥；**没有固定句式**、**没有禁技术参数**、**没有禁主观评价**。

## 世代 2 · v3.6.7 固定句式（2026-09-22 早）

**来源**：`memory/2026-09-22.md:184`（记忆记录，非逐字原文，括号式模板部分为逐字）。

```
- chinese_description: 中文简介。**固定句式**：「{主体}（组合 或 艺人）于 {YYYY 年 M 月 D 日} 在 {活动名} 表演 {曲目}」
```

要点：
- 主体括号内只写「组合」/「艺人」两字身份；
- 各段缺失就省略对应片段（日期缺→省「于 …」；无活动名→省「在 …」；无曲目→省「表演 …」）；
- 日期取 `performance_date`，为空退上传日期；
- 非表演类（OfficialMV / Teaser / SpecialVideo）把「表演」换成贴切动词（MV 用「发布」、访谈用「出演」）；
- 补充句**最多 1 句，且仅当来源简介 `description` 明确写到**；
- ❌ 禁技术参数、❌ 禁主观评价。

## 世代 3 · v3.6.11 严格句式（2026-09-22 晚）· 逐字原文

`ai_service.py:70–88`（**已被世代 4 替换，此处仅存档**）：

```
- chinese_description: 中文简介。**固定句式**：「{主体}于 {YYYY 年 M 月 D 日} 在 {活动名} 表演歌曲 {曲目}。」
  —— 组合示例：「STAYC组合于 2023 年 2 月 17 日在 Music Bank 表演歌曲 Teddy Bear。」
  —— 艺人示例：「艺人张元英于 2023 年 2 月 17 日在 Music Bank 表演歌曲 Teddy Bear。」
  再视来源简介补 0-1 句依据。
  - 主体（身份词位置**两种写法不同，别搞混**）：
    · 团体 → **组合名在前、身份词在后**，写成「STAYC组合」「NewJeans组合」；
    · 个人直拍 / 个人舞台 / solo 艺人 → **身份词在前、艺名在后**，写成「艺人张元英」「艺人IU」。
    两种都**只写「组合」或「艺人」两个字**，不写其它说明，**绝不用括号包裹**。
  - 日期：取 performance_date；为空退回上传日期。都拿不到就省略「于 … 」整段。
  - 活动名：取 event_name（如 M COUNTDOWN、XX 校庆）；为空就省略「在 … 」整段。
  - 曲目：取官方英文曲名（多首用 & 连接）；**动词后固定带「歌曲」二字**（写成「表演歌曲 Teddy Bear」，不能只写「表演 Teddy Bear」）；
    为空就省略整段。
  - 非表演类素材（OfficialMV / Teaser / SpecialVideo 等）把「表演」换成贴切动词（如 MV 用「发布」、访谈用「出演」），不要硬套「表演」；
    「歌曲」二字随动词搭配取舍（「发布歌曲 X」通顺就带，「出演歌曲 X」不通就不带）。
  - 补充句（可选，**最多 1 句**）：**仅当来源简介（description）明确写到**时才补，例如「翻唱自 XXX 的《YYY》」「在特别布置的舞台上表演」「该场为出道舞台」；**来源简介没写就绝对不补**。
  - ❌ 禁止出现画质 / 帧率 / 分辨率 / 编码 / 码率 / 文件大小 / 时长 / 下载平台等技术参数。
  - ❌ 禁止主观评价与猜测（「精彩绝伦」「引爆全场」「粉丝反响热烈」之类），只陈述可核实的事实，严禁添油加醋。
  - 不要照抄来源简介原文；不要分点、不要 markdown、不要用引号包裹整段；**句末用中文句号「。」收尾**；
    **全文不得出现括号包裹的身份标注**（写「STAYC组合」「艺人张元英」，不写「STAYC（组合）」「张元英（艺人）」）。
```

**兜底清洗**（与提示词配套）：`_normalize()` → `_strip_identity_parens()`，
只剥 `（组合）`/`（艺人）` 括号 + 把后置「X 艺人」翻成前置「艺人 X」。
⚠ 「表演 → 表演歌曲」**刻意不做机械兜底**（会误伤「表演 2 首」），只靠提示词。
守卫测试：`backend/test_ai_description_prompt.py`。

## 世代 4 · 当前（v3.6.12，2026-09-23）· 恢复原版 + 可编辑

**业主口径**：「中文简介提示词恢复为原版，并在 AI 设置中增加修改提示词和恢复默认的功能。」

两个变化：

**① 默认回退世代 1（原版自由口径）** —— 逐字等于上面世代 1 那一行。
落点从「写死在 `SYSTEM_PROMPT`」改为「模板 + 注入」：

| | |
|---|---|
| `_SYSTEM_TEMPLATE` | 原 `SYSTEM_PROMPT` 全文，其中该条退化为**裸占位符** `{desc_rule}` |
| `DEFAULT_DESC_RULE` | 内置默认 = 世代 1 原版那一行（**含** `- chinese_description: ` 前缀） |
| `build_system_prompt(desc_rule)` | `_SYSTEM_TEMPLATE.replace("{desc_rule}", rule)`；空 → 回落默认；规则里无 `chinese_description` 字样 → **自动补前缀**（防呆） |
| `SYSTEM_PROMPT` | 保留原名 = `build_system_prompt()`，即默认渲染结果（向后兼容） |

⚠ 必须用 `replace` 而非 `str.format` —— 模板正文含 JSON 示例（`{"song": ...}`）。

**② 可自定义 + 恢复默认**（`ingest_ai` 分区新增 `desc_prompt`）：

- 后端 `IngestAiSettings.desc_prompt: str = ""`，空串 = 用后端内置默认；
- `POST /api/ai/suggest` 读设置 → `build_system_prompt(desc_prompt)` → `suggest_ingest(system_prompt=...)`；
- 前端「AI 设置」页新增「中文简介提示词」textarea + 行内「恢复默认」；
- 出站归一化：内容与默认文本逐字一致 → 存**空串**（跟随后端默认，后端升级默认可自动生效）；回读时空串再回填默认文本供显示；
- 守卫测试 `backend/test_ai_description_prompt.py`（56 断言）已按新口径重写。

**`SYSTEM_PROMPT` 体积**：4817 字符（世代 3）→ **3781 字符**（世代 4 默认）。

## 顺带发现：同一份 `.pyc` 里还留着原版的「画质后缀」条款

原版 `SYSTEM_PROMPT` 的「5️⃣ 后缀括号」段有这两条，正是用户在 v3.6.5 / v3.6.6 要求**去掉**的内容：

```
- 画质/帧率（若支持 4K、8K、60p）→ 必须追加标注（如 [Music Bank FanCam 4K]、[M COUNTDOWN FanCam 4K60p]）。
- 判断依据来自 video_info 的技术字段：4K = width ≥ 3840，8K = width ≥ 7680，60p = fps ≥ 55。
```

另外原版是 **9 类枚举**（`SpecialStage` 吃掉了「合作舞台」），当前是 **11 类**（`CollabStage` 独立）；
原版「时长 < 70 秒 → ShortVideo」现改为「<70 秒的混剪/合集用 MixEdit」。
